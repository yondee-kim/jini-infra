## User 엔티티 PK를 UUIDv7로 전환

### 배경
모놀리식 jini의 User는 `@GeneratedValue(strategy = IDENTITY)` 기반
auto-increment Long PK를 썼다. MSA로 분리하면서 PK 전략을 UUIDv7로 바꿨다.

### 왜 UUIDv7인가
- MSA에서는 여러 서비스가 각자 ID를 생성해도 충돌이 없어야 한다.
  DB 시퀀스에 의존하는 auto-increment는 이 요구에 맞지 않는다.
- 랜덤 UUID(v4)를 PK로 쓰면 INSERT마다 B-tree 인덱스의 임의 위치에
  삽입되어 페이지 분할이 잦고 인덱스 성능이 저하된다.
- UUIDv7은 앞부분이 타임스탬프라 시간순으로 정렬된다. 항상 인덱스
  끝쪽에 추가되어 auto-increment에 가까운 삽입 성능을 낸다.
  → 분산 유일성 + 인덱스 성능을 모두 확보.

### 구현
Hibernate 6.5+가 UUIDv7을 네이티브 지원하므로 별도 라이브러리 불필요.

    @Id
    @GeneratedValue
    @UuidGenerator(style = UuidGenerator.Style.TIME)   // TIME = UUIDv7
    private UUID id;

- `style = TIME`을 반드시 명시해야 UUIDv7이 생성된다.
  생략 시 기본값은 랜덤(v4)이라 정렬 이점을 잃는다.
- 타입은 String이 아닌 `UUID`로 잡았다. PostgreSQL의 네이티브 uuid
  타입(16바이트)에 매핑되어 String(36자)보다 저장·인덱스 효율이 좋다.
- id는 Hibernate가 persist 시점에 채우므로 생성자에서 건드리지 않는다.

Repository의 PK 제네릭도 Long → UUID로 변경.

    public interface UserRepository extends JpaRepository<User, UUID> { ... }

### 확인
`ddl-auto: update`로 앱 기동 시 users 테이블이 `id uuid` 컬럼으로 생성됨을 확인.
