## JWT를 userId(UUID) 기반으로 개편

### 배경
기존 모놀리식은 JWT의 subject에 email을 담았다. 하지만 email은 변경될 수
있는 PII이고, MSA에서 chat 서비스가 이를 식별자로 쓰면 결합도가 높아진다.
subject를 안정적인 userId(UUID)로 바꾸고, email·nickname은 부가 claim으로 분리했다.

### 변경
- JwtProvider.createToken(email) → createToken(UUID userId, String email, String nickname)
  - sub = userId, claim에 email/nickname 추가
- 추출 메서드: getUserId()(sub에서 UUID 복원), getEmail()(claim에서)
- AuthService.login: createToken 호출을 user.getId() 포함하도록 변경
- OAuth2SuccessHandler: userInfo에는 우리 DB의 userId가 없으므로
  UserRepository.findByEmail로 User를 조회해 userId 확보 후 토큰 발급
  (OAuth2UserService가 로그인 시 findOrCreateUser로 이미 저장하므로 조회 성공 보장)
- 리다이렉트 URI를 하드코딩(/chat.html)에서 ${app.oauth2.redirect-uri} 설정값으로 외부화

### 트러블슈팅
- ClientRegistrationRepository 빈 누락으로 기동 실패
  → application.yml에 OAuth2 client 등록 정보(google/naver) 이전 필요.
    naver redirect-uri 포트를 8080→8081로 수정.

### 확인
로그인 응답 JWT를 디코딩해 sub가 UUID, email·nickname이 claim에 있음을 확인.
