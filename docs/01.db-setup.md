## 트러블슈팅: docker-compose 이중 DB 구성 시 포트·볼륨·DB생성 문제

### 배경
모놀리식 jini를 jini-auth / jini-chat 두 서비스로 분리하면서, 각 서비스가
독립된 PostgreSQL을 갖도록(Database per Service) docker-compose에 DB 컨테이너를
두 개(auth_db:5432, chat_db:5433) 구성했다. 기존 jini는 단일 DB(chatdb)
컨테이너만 썼기 때문에, 이중 구성으로 바꾸는 과정에서 세 가지 문제를 연달아 겪었다.

### 증상 1: database "auth_db" does not exist

    GenericJDBCException: Unable to obtain isolated JDBC connection
    [FATAL: database "auth_db" does not exist]

접속 정보(.env의 DB_URL)는 맞는데 auth_db가 없다는 에러.

#### 원인
Postgres 이미지의 `POSTGRES_DB` 환경변수는 **볼륨이 비어 있을 때 최초 1회만**
DB를 생성한다. 기존 jini compose(chatdb)로 띄운 볼륨이 남아 있어, 나중에
`POSTGRES_DB: auth_db`로 바꿔도 초기화 로직이 실행되지 않았다.

#### 해결
볼륨을 삭제하고 재생성.

    docker compose down -v      # 컨테이너 + 볼륨 완전 삭제
    docker compose up -d        # 빈 볼륨에서 재생성 → auth_db, chat_db 생성됨

`-v`가 핵심. 붙이지 않으면 기존 볼륨이 유지되어 DB가 생성되지 않는다.
확인: `docker exec -it jini-postgres-auth psql -U postgres -l`

### 증상 2: port is already allocated

    Bind for 0.0.0.0:5432 failed: port is already allocated

auth 컨테이너가 5432를 잡지 못하고 Created 상태에서 멈춤.

#### 원인
`docker ps -a`로 확인하니 기존 jini의 옛 컨테이너(jini-postgres-1)가 51분째
5432를 점유하고 있었다. compose를 새로 띄워도 옛 컨테이너가 살아 있어 포트가 충돌.

#### 해결
옛 컨테이너 제거 후 재기동.

    docker rm -f jini-postgres-1
    docker compose up -d

(만약 로컬에 설치된 PostgreSQL 서비스가 5432를 점유한 경우라면,
호스트 포트를 5442 등으로 바꾸고 .env의 DB_URL 포트도 함께 수정한다.)

### 포트 매핑 이해: 0.0.0.0:5433->5432

chat 컨테이너의 포트 표기 `0.0.0.0:5433->5432/tcp`는 정상이다.

- 왼쪽(5433): 호스트 포트 — PC에서 접속할 포트
- 오른쪽(5432): 컨테이너 내부 포트 — Postgres가 실제 도는 포트

Postgres는 컨테이너 안에서 항상 5432로 돈다(auth/chat 동일). 호스트에서 둘 다
5432를 열 수 없으므로 chat만 호스트 쪽을 5433으로 매핑했다. 컨테이너끼리는
격리되어 내부 포트가 같아도 충돌하지 않는다. 따라서 애플리케이션 접속 URL은
호스트 포트를 쓴다:

    jini-auth → jdbc:postgresql://localhost:5432/auth_db
    jini-chat → jdbc:postgresql://localhost:5433/chat_db

### 교훈
- `POSTGRES_DB`는 볼륨 최초 생성 시에만 적용된다. DB 이름/구성을 바꿨는데
  반영이 안 되면 `docker compose down -v`로 볼륨을 밀고 다시 띄운다.
  단, 데이터가 쌓인 뒤에는 -v가 전체 삭제이므로 주의.
- 포트 충돌 시 `docker ps -a`로 점유 컨테이너부터 확인한다. 옛 컨테이너가
  범인인 경우가 많다. 컨테이너가 아니면 로컬 서비스(netstat)를 의심한다.
- 포트 매핑은 항상 `호스트:컨테이너` 순. 접속 URL에는 호스트 포트를 쓴다.
