## OAuth2 콘솔 콜백 URI 설정 방법 (google/naver)

### 배경
구글·네이버 개발자 콘솔에는 이전 프로젝트(whybuychat) 기준의 콜백 URI와
앱 이름이 등록되어 있었다. jini-auth는 8081 포트에서 동작하므로, 콘솔에
등록된 콜백 URI가 auth 서버 주소와 일치하지 않으면 인증 후 리다이렉트가
실패한다. OAuth2는 콘솔 등록 콜백 URI와 요청 콜백 URI가 정확히 일치해야
하므로, 콘솔 쪽 등록값을 jini-auth 주소로 맞췄다. 아울러 로그인 동의 화면에
노출되는 앱 이름도 jini로 변경했다.

### 용어 구분
OAuth2 흐름에는 두 종류의 리다이렉트 주소가 있다. 혼동하지 않도록 구분한다.
- 콜백 URI (provider redirect): 구글/네이버가 인증 후 auth 서버로 돌려보내는 주소.
  Spring Security 규약상 `/login/oauth2/code/{provider}` 경로를 사용한다.
  이 값이 콘솔 등록 대상이다.
- 앱 최종 리다이렉트 (app.oauth2.redirect-uri): auth가 JWT 발급 후 사용자를
  보낼 화면 주소. `.env`의 APP_OAUTH2_REDIRECT_URI로 관리하며 콘솔과 무관하다.

### 콘솔 작업 (코드 아님, 외부 설정)

1. 콜백 URI 등록
- 구글 — Google Cloud Console > API 및 서비스 > 사용자 인증 정보
  (https://console.cloud.google.com/apis/credentials)
  OAuth 2.0 클라이언트 ID의 "승인된 리디렉션 URI"에 아래 추가:
    http://localhost:8081/login/oauth2/code/google
  (구글 콜백은 yml에 명시하지 않았고 Spring Security 기본 경로를 따른다.)
- 네이버 — 네이버 개발자센터 > 내 애플리케이션 > API 설정
  (https://developers.naver.com/apps/#/myapps)
  Callback URL에 아래 등록:
    http://localhost:8081/login/oauth2/code/naver
  (이 값은 application.yml의 naver redirect-uri와 정확히 일치해야 한다.)

2. 동의 화면 앱 이름 변경 (구글)
- 로그인 시 동의 화면에 뜨는 "OO(으)로 이동" 문구의 OO는 콘솔에 등록된
  앱 이름이다. 코드가 아니라 콘솔 설정값이다.
- Google Cloud Console > API 및 서비스 > OAuth 동의 화면 > 브랜딩
  (https://console.cloud.google.com/auth/branding)
  "앱 이름" 필드를 whybuychat → jini 로 변경.
- 게시 상태가 "테스트"면 대개 즉시 반영된다. 게시 상태에 따라 재검토·
  반영 지연이 있을 수 있다.
- 네이버는 "애플리케이션 이름"이 동의 화면에 노출되며, API 설정 화면에서
  동일하게 변경한다.

### 코드/설정 대조
- application.yml: naver redirect-uri = http://localhost:8081/login/oauth2/code/naver
  → 콘솔 등록값과 일치 확인.
- 구글은 yml에 redirect-uri 미명시 → 기본 경로 사용 → 콘솔에 기본 경로 등록.
- client-id/secret은 기존 콘솔 앱을 재사용하는 경우 변경 불필요.
  (새 앱을 생성했다면 .env의 GOOGLE_CLIENT_ID/SECRET, NAVER_CLIENT_ID/SECRET 교체 필요.)

### 확인
콘솔에서 콜백 URI 및 앱 이름 변경 완료. 이후 OAuth2 로그인 플로우 실제 동작 검증 예정.
